# TF-MTL-CBRKAN: Multi-Task Learning for Transcription Factor Binding Prediction

[![Python 3.8+](https://img.shields.io/badge/Python-3.8%2B-blue.svg)](https://www.python.org/)
[![PyTorch](https://img.shields.io/badge/PyTorch-2.x-orange.svg)](https://pytorch.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Multi-task learning (MTL) framework for predicting transcription factor (TF)
binding from DNA sequences. A **shared CBR-KAN backbone** (CNN + BiLSTM + KAN)
is trained jointly across TFs that are grouped by sequence-similarity clusters;
each TF gets its own lightweight **KAN prediction head**. Compared with
single-task training, the MTL model improves the ROC-AUC of most TFs
(81.6% positive transfer, paired t-test p = 1.9e-27) while reducing total
parameters by ~70% (1.90B → 553M) and training time by 3.66×.

This repository contains the complete reproducible pipeline:
clustering → MTL training → single-task baselines → paired comparison.

## Architecture

```
DNA sequence (200 bp, 3-mer tokenized)
        │
        ▼
┌───────────────────────────────┐
│  CBR-KAN Shared Backbone       │  Embedding → Multi-CNN (3 branches)
│  (shared by all TFs)           │           → BiLSTM → LayerNorm → [256]
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  per-TF KAN heads (routed)     │  KAN[256, 32, 2] × N_TF
└───────────────────────────────┘
        │
        ▼
   binding / non-binding
```

- **Shared backbone**: three parallel CNN streams (kernel sizes 1/9/11 patterns)
  fused with a 2-layer BiLSTM; features summed and normalized to 256-d.
- **Per-TF heads**: one Kolmogorov-Arnold Network (KAN) head per TF
  (efficient-kan implementation, vendored under `src/efficient_kan/`).
- **Training**: samples carry their TF identity; the batch is routed to the
  correct head. Early stopping on validation ROC-AUC (patience 15),
  ReduceLROnPlateau (patience 10), seed 42, 60/20/20 split per TF.

## Quick start (demo, CPU, ~10 min)

A tiny demo FASTA dataset (300 pos + 300 neg sequences for SP140 / SP140L,
subsampled from the real ChIP-seq data) is included under
`data/demo_fasta/` so the pipeline can be exercised end-to-end on any
machine without downloading the full data:

```bash
bash run_demo.sh
```

This trains CBR-KAN MTL on one 2-TF cluster, trains the single-task
baselines for the same TFs, and runs the paired MTL-vs-Single comparison.
All outputs land in `results/` (ignored by git). Expect MTL ROC-AUC ≈ 0.85
on the demo subset (real-data performance is reported in the paper).

## Full-data experiment

### 0. Obtain the full dataset

The full training set is one FASTA pair per TF (12 GB total, 1,043 TFs):

```
<data_root>/
├── <GSM_ID>.pos.fasta    # positive ChIP-seq peak-centered sequences
└── <GSM_ID>.neg.fasta    # negative control sequences
```

Set the data root with `--data-root` (or the `TFMTL_DATA_ROOT` environment
variable). Point the scripts at your dataset directory; the included
`data/cluster_t098_csvs/*.csv` files already map each TF to its `GSM_ID`.

The paper uses **204 MTL clusters** (sequence-similarity clustering,
t098 threshold). The per-cluster TF lists are provided directly as
**204 CSV files** in `data/cluster_t098_csvs/` — one CSV per cluster
(filename suffix = cluster ID, e.g. `cluster_005_t098.csv`), each row
mapping a TF to its `GSM_ID`.

**Data availability:** the complete FASTA dataset (all 1,043 TFs, 12 GB,
1043 × `.pos.fasta` + `.neg.fasta`) is included locally at
`data/full_fasta/` on the author's machine and is available for the
Editorial Board and reviewers during the peer-review process. For a
public release it will additionally be deposited in a public repository
(e.g. Zenodo) upon acceptance; for now, point `--data-root` at
`data/full_fasta` to reproduce the full experiment.

## Usage

### 1. (Optional) Rebuild the training plan from clustering output

The 204-cluster training plan is **auto-built from
`data/cluster_t098_csvs/`** by `train_all_clusters.py` (Section 3), so no
plan JSON is shipped. If you have raw clustering output and a TF-info
CSV (TF → GSM_ID, with performance columns), you can regenerate the
cluster CSVs + plan yourself:

```bash
python scripts/generate_plan.py \
    --cluster-dir <dir-with-cluster_*.txt> \
    --tf-info <path/to/tf_info.csv> \
    --output-csv-dir data/cluster_t098_csvs \
    --output-json results/cluster_mtl_t098_plan.json
```

### 2. Train MTL on one cluster (smoke test)

```bash
python scripts/train_mtl_cluster.py \
    --tf-list data/cluster_t098_csvs/cluster_005_t098.csv \
    --output-dir results/cluster_005 \
    --data-root /path/to/fasta_datasets \
    --device cuda:0
```

### 3. Train all MTL clusters (full experiment, 204 clusters)

```bash
python scripts/train_all_clusters.py \
    --results-base results/mtl_v5_t098 \
    --log-dir logs \
    --data-root /path/to/fasta_datasets
```

The plan is auto-built from the 204 CSVs in `data/cluster_t098_csvs/`;
clusters with an existing valid `summary.json` are skipped (resumable).

### 4. Single-task baselines

```bash
python scripts/train_single.py \
    --tf-name SP140 --gsm-id GSM2398967 \
    --data-root /path/to/fasta_datasets \
    --output results/single/SP140_GSM2398967
```

### 5. Paired comparison (MTL vs Single)

```bash
python scripts/compare_mtl_vs_single.py \
    --single-dir results/single_1043 \
    --mtl-dir results/mtl_v5_t098 \
    --cluster-csv-dir data/cluster_t098_csvs \
    --output-dir results
```

Output: `results/comparison_cbrkan_mtl_v5_t098.csv` with 7 paired metrics
per TF (ROC-AUC, PR-AUC, Accuracy, Precision, Recall, F1, MCC) plus
Delta columns, and a printed statistical summary.

## Results (t098 clustering, 767 TFs / 204 MTL clusters)

| Metric | Single-task | MTL | Δ (MTL − Single) | Positive (%) | p value |
|---|---|---|---|---|---|
| ROC-AUC | 0.9344 | 0.9409 | +0.0065 ± 0.0160 | 81.6% (626/767) | 1.9e-27 |
| Efficiency | 1.90B params / 191.75h | 553M params / 52.4h | −70.9% / 3.66× | — | — |

- Cluster-level: +0.0036 ± 0.0067, 80.4% (164/204) positive, p = 6.4e-13;
  all 12 clusters with ≥10 TFs positive (min +0.0036).
- Full 7-metric per-TF table: written by the comparison script (Section 5)
  to `results/comparison_*.csv` (per-TF and cluster summaries).
